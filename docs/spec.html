Zoobrik: слова учатся гнёздами, а не россыпью

Приложение для изучения английских слов и грамматики. Интервальные повторения по алгоритму Anki (FSRS), колоды в виде простых YAML-файлов в GitHub-репозитории, задания на шаблонах, которые можно переверстать целиком.

Платформа: Web / PWA Алгоритм: FSRS-6 Планирование: гибрид Шаблоны: Nunjucks + CSS + JS Хранилище: GitHub

01Концепция

В Anki каждая сторона слова — отдельная карточка со своим расписанием. Карточки разных слов перемешиваются, и за сессию человек видит сотню несвязанных фрагментов. Zoobrik строит работу вокруг карточки изучения (слово, фраза, грамматическое правило). За один цикл её проверяют несколькими разными заданиями, перемешанными с заданиями соседних слов той же темы.

принцип 1
Одна карточка — много граней

У слова есть навыки: узнать, вспомнить, расслышать, написать, употребить в предложении. У каждого навыка свой интервал.

принцип 2
Много заданий за один цикл

Если пора повторить хотя бы один навык, слово получает в текущем цикле 2–5 разных заданий. Они разнесены по циклу вперемешку с соседями, подряд не идут.

принцип 3
Тема держит фокус

Очередь собирается по темам: 3–5 слов одной темы чередуются между собой, потом следующая тема.

принцип 4
Новое — порциями с гейтом

Следующая порция слов темы открывается только после того, как текущая закрепилась.

принцип 5
Папка — это всё о слове

Контент, задания, прогресс, медиа и свои шаблоны лежат в папке карточки. При публикации колоды прогресс вырезается.

принцип 6
Задание видно до показа

Каждое задание — явная запись в карточке: шаблон и конкретные данные. Автор проверяет и одобряет его заранее, вёрстку можно переопределить на любом уровне.

02Модель данных

Колода→Тема→Карточка слова→Задания→Шаблон каждого задания

Ключевая идея: задание — явная запись в карточке. В карточке лежат конкретные данные каждого задания: что показать, какой правильный ответ, какие подкидыши. Шаблон знает, как эти данные сверстать и как проверить ответ, но сам ничего не придумывает в момент показа. Всё, что увидит ученик, можно открыть, проверить и поправить заранее.

СущностьЧто этоГде лежит
КолодаНабор тем и общие настройки: лимиты, FSRS, голос, подключённые пакеты шаблонов. Одна колода — один репозиторий.deck.yaml
ТемаГруппа карточек: порядок ввода, размер порции, зависимости. Может содержать свои шаблоны и задания на несколько слов сразу.topics/<тема>/topic.yaml
КарточкаВсё про одно слово, фразу или правило: контент, список заданий, прогресс, медиа, свои шаблоны.папка topics/<тема>/<слово>/
ЗаданиеСсылка на шаблон, навык, который тренирует, статус и params — конкретные данные для этого шаблона.card.yaml → exercises[]
ШаблонТип задания: схема параметров, способ проверки ответа, вёрстка, стили, логика, рецепт сборки черновиков.core/, templates/, папка темы или карточки
НавыкГрань знания слова со своим расписанием FSRS. Задания тренируют навыки.card.yaml → progress.skills
ЖурналПолная история всех ответов, только дописывается.journal/<год-месяц>/<устройство>.tsv

Одно задание может тренировать несколько навыков: listen-type — и listen, и spell. Навык без единого готового задания в расписание не попадает, а редактор предупреждает об этом.

03Формат файлов

Согласовано

Данные — YAML 1.2, длинные тексты (заметки, теория правил) — Markdown внутри YAML. Для каждого файла есть JSON Schema: VS Code и JetBrains по ней подсказывают поля и подсвечивают ошибки. Почему YAML: он читается глазами, позволяет комментарии, многострочный текст и аккуратные диффы в git. JSON шумный и без комментариев, TOML неудобен для списков объектов вроде заданий.

Карточка целиком

topics/travel-airport/luggage/card.yaml 
id: luggage
kind: word

# ── 1. Контент: факты о слове, из них собираются черновики заданий
content:
  en: luggage
  ru: багаж
  alt_ru: [вещи, чемоданы]
  pos: noun
  ipa: ˈlʌɡ.ɪdʒ
  audio: { file: luggage.mp3, engine: kokoro-1.0, voice: bf_emma }
  image: luggage.webp
  note: |
    Неисчисляемое: **a piece of luggage**, но не ~~a luggage~~ и не ~~luggages~~.
  confusables: [baggage, language]
  examples:
    - id: ex1
      en: I can't find my luggage.
      ru: Я не могу найти свой багаж.
      audio: luggage.ex1.mp3
    - id: ex2
      en: How many pieces of luggage do you have?
      ru: Сколько у вас мест багажа?
      audio: luggage.ex2.mp3

# ── 2. Задания: явные, проверенные, каждое видно и редактируется
exercises:
  - id: intro
    template: intro
    status: ready
    params: { word: luggage, translation: багаж, image: luggage.webp, audio: luggage.mp3, examples: [ex1, ex2] }

  - id: e1
    template: en-ru-choice
    skill: recognize
    status: ready
    params:
      word: luggage
      audio: luggage.mp3
      answer: багаж
      options: [багаж, посадочный талон, выход на посадку, таможня]

  - id: e2
    template: ru-en-type
    skill: [recall, spell]
    status: ready
    params:
      prompt: багаж
      answer: luggage
      hint: "l _ _ _ _ _ e"

  - id: e3
    template: sentence-build-ru-en
    skill: context
    status: ready
    from: examples.ex1                # собрано рецептом из примера ex1
    params:
      prompt: Я не могу найти свой багаж.
      answer: I can't find my luggage.
      accept: [I cannot find my luggage.]
      extra: [luggages, the, found]
      audio: luggage.ex1.mp3

  - id: e4
    template: listen-type
    skill: [listen, spell]
    status: draft                     # черновик: в ротацию не попадает
    from: examples.ex2
    params:
      audio: luggage.ex2.mp3
      answer: How many pieces of luggage do you have?

  - id: e5
    template: ./views/uncountable     # свой шаблон только для этого слова

    status: ready
    params:
      question: Как сказать «у меня три чемодана багажа»?

      wrong: [I have three luggages., I have three luggage.]

Журнал

Слово повторяется годами, переходит из Review в Relearning и обратно, за жизнь набирает 1000–2000 ответов. Поэтому полная история лежит отдельно от карточки, а карточка хранит итог: состояние навыков, счётчики, статистику заданий и хвост из 20 ответов. Размер card.yaml не растёт со временем и держится в пределах 3–8 КБ.

journal/2026-10/iphone.tsv

2026-10-05T14:08:12Z  travel-airport/luggage    e1      recognize 3      1900
2026-10-05T14:10:31Z  travel-airport/luggage    e2      recall    1      7400  typo:lugage

  • Каждое устройство пишет только в свой файл и только дописывает. При синхронизации журнал никогда не конфликтует.
  • Около 70 байт на ответ. 300 ответов в день — примерно 7–8 МБ в год, git хорошо сжимает такой текст.
  • Журнал — источник истины. progress в карточке можно пересчитать из него: строки после as_of прогоняются через FSRS.
  • Журнал нужен оптимизатору FSRS, календарю занятий и истории слова в статистике.

04Как собирается задание

Согласовано

Три слоя, каждый в своём файле и со своей зоной ответственности:

шаблон · manifest.yaml + view.njk
Как выглядит и как проверять

Объявляет параметры, которые ему нужны, способ проверки ответа и навыки, которые тренирует. Пишется один раз, используется тысячами карточек.

задание · card.yaml → exercises[]
Что именно спросить

Конкретные значения параметров для одного слова. Проверено автором, хранится в карточке.

показ · runtime
Как это встречается в сессии

Планировщик выбирает задание, приложение передаёт его params в шаблон, проверяет ответ, ставит оценку, пишет журнал.

Путь одного задания: от файла до экрана

Задание e3 из карточки luggage, шаблон sentence-build-ru-en.

Шаг 1. Шаблон объявляет параметры

core/sentence-build-ru-en/manifest.yaml 
id: sentence-build-ru-en
name: Собери перевод (ru → en)
trains: [context]
reveals: [en]
params:                            # схема → форма в редакторе и валидация
  prompt: { type: text,  label: Предложение на русском, required: true }
  answer: { type: text,  label: Правильный перевод, required: true }
  accept: { type: list,  of: text, label: Тоже верные варианты }
  extra:  { type: list,  of: word, label: Лишние слова, min: 2, max: 5 }
  audio:  { type: audio, label: Озвучка ответа }
check:                             # как сравнивать ответ
  type: tokens                       # exact | fuzzy | tokens | choice | custom
  expected: params.answer
  also: params.accept
recipe:                            # как собрать черновики из контента карточки
  for_each: content.examples
  from: examples.{{ item.id }}
  params:
    prompt: "{{ item.ru }}"
    answer: "{{ item.en }}"
    extra:  "{{ suggest.extra(item.en, 3) }}"   # формы слова, артикли, слова темы
    audio:  "{{ item.audio }}"
lint:                              # проверки при сохранении
  - extra не пересекается со словами answer
  - в answer не больше 12 слов

Шаг 2. Задание в карточке заполняет параметры

- id: e3
  template: sentence-build-ru-en
  skill: context
  status: ready
  from: examples.ex1
  params:
    prompt: Я не могу найти свой багаж.
    answer: I can't find my luggage.
    accept: [I cannot find my luggage.]
    extra: [luggages, the, found]
    audio: luggage.ex1.mp3

Шаг 3. Вёрстка получает данные

В шаблон передаются: params — параметры задания, card — весь контент карточки (картинка, транскрипция, заметка), exercise (id, навык), topic, mode (learn или review), seed для перемешивания.

core/sentence-build-ru-en/view.njk 
{% set bank = (params.answer | tokens) | concat(params.extra) | shuffle(seed) %}
<div class="prompt">
  <span class="lang">RU</span>
  <p class="source">{{ params.prompt }}</p>
  {% if card.note %}<button data-zb="hint">Подсказка</button>{% endif %}
</div>
<div class="answer" data-zb-slot="answer"></div>
<div class="bank">
  {% for w in bank %}<button class="chip" data-zb-chip="{{ w }}">{{ w }}</button>{% endfor %}
</div>
<button data-zb="submit">Проверить</button>

Шаг 4. Ответ проверяется по манифесту

Ученик собрал «I can't find my luggage.»→zb.answer({ tokens })→check: tokens — совпало с answer→оценка Good→FSRS: context s 25 → 41 дн.→строка в журнал, итог в progress

Шаблон не решает, верен ли ответ: он только передаёт ответ ученика. Проверка описана в манифесте, поэтому одинакова в любой вёрстке. Если нужна особая логика, есть check.type: custom с функцией check(answer, params) в logic.js.

Откуда берутся задания

СпособКак работаетКогда удобен
Черновики по рецептамКнопка «Собрать черновики» в карточке или zoobrik build topics/travel-airport. Для каждого шаблона из deck.recipes выполняется его recipe, получаются задания со статусом draft. Уже существующие не дублируются.Основной поток: из 2 примеров получается 7–9 заданий за секунду
Вручную через форму«+ Задание» → выбрать шаблон → форма строится по params из манифеста → живое превью → сохранить.Особые задания, исправление черновика
Прямо в YAMLДописать запись в exercises в редакторе кода. Схема подсказывает поля.Тем, кому удобнее текст
Массово из таблицыИмпорт CSV в выбранный шаблон: столбцы сопоставляются с params, строка — карточка.Перенос готовых материалов

Проверка автором: статусы

  • draft — собран рецептом или создан, но не проверен. В сессии не показывается.
  • ready — проверен в превью и одобрен. Участвует в ротации.
  • off — выключен, но хранится вместе со статистикой.
  • stale — выставляется автоматически, если изменился источник из from (например, поправили пример ex1). Задание продолжает показываться, а в редакторе предлагается пересобрать его и сравнить с текущей версией.

При сохранении запускаются проверки: схема параметров, правила lint из манифеста, наличие медиа. Плюс общие предупреждения: «у навыка listen нет ни одного готового задания», «задание e2 верно в 99% ответов за 300 показов — слишком лёгкое».

Свои задания для конкретного слова

Если готового шаблона не хватает, шаблон кладётся прямо в папку карточки и подключается относительным путём. Пример: для luggage нужно отдельно отработать неисчисляемость с картинкой.

luggage/views/uncountable/
├── manifest.yaml     # params: question, right, wrong[], picture; check: choice
├── view.njk
└── style.css
- id: e5
  template: ./views/uncountable
  skill: context
  status: ready
  params: { question: …, right: …, wrong: […], picture: luggage.webp }

Для разовой мелочи манифест не обязателен: задание может нести вёрстку внутри себя.

- id: e6
  template: inline
  skill: recognize
  status: ready
  check: { type: choice, expected: "a piece of luggage" }
  view: |
    <p class="q">Что можно сказать?</p>
    {% for o in ["a luggage", "a piece of luggage", "luggages"] | shuffle(seed) %}
      <button data-zb-choice="{{ o }}">{{ o }}</button>
    {% endfor %}
  style: |
    .q { font-size: 1.3rem }

Переопределить вёрстку на любом уровне

Шаблон ищется по каскаду, от частного к общему. Первый найденный побеждает:

карточка

travel-airport/views/X→колода

  • Целиком: положить на нужный уровень папку с тем же id. Например, travel-airport/views/en-ru-choice/ меняет вёрстку выбора перевода только в этой теме.

Такое задание попадает в цикл, когда в нём оказываются хотя бы 3 из его карточек. Каждая пара оценивается отдельно и идёт в навык своей карточки.

Подкидыши и отвлекающие варианты

Подкидыши подбираются при сборке черновика, а не в момент показа. Помощник рецепта suggest.extra(text, n) / suggest.options(word, n) предлагает варианты, автор правит их в форме, и они сохраняются в params. Источники по приоритету:

  • confusables карточки: luggage → baggage, language;
  • batch — слова текущей порции, чтобы учиться различать соседей;
  • topic — та же тема и часть речи;
  • morphology — формы того же слова для сборки предложений: go / goes / went / going, артикли a / an / the, предлоги;
  • plugin — внешний генератор через хук suggest.provide.

Банк слов для сборки предложения: токены правильного ответа плюс 2–4 подкидыша, перемешанные с сидом от id задания + дата. Повторный показ в тот же день даёт ту же раскладку, а на следующий день — новую.

07Интервальные повторения: FSRS из Anki

Согласовано

Берём FSRS — алгоритм, который в Anki включён по умолчанию с версии 23.10. Реализация — ts-fsrs от авторов алгоритма, чтобы не расходиться с Anki в числах. У каждого навыка три переменные:

  • Stability (S) — через сколько дней вероятность вспомнить упадёт до 90%.
  • Difficulty (D) — от 1 до 10, насколько трудно навык поддаётся укреплению.
  • Retrievability (R) — вероятность вспомнить прямо сейчас, вычисляется из S и прошедшего времени.

Оценки

Снова1 · Again · клавиша 1
Трудно2 · Hard · клавиша 2
Хорошо3 · Good · клавиша 3 / пробел
Легко4 · Easy · клавиша 4

Формулы (FSRS-6)

# кривая забывания, t — дни с последнего повторения
R(t, S) = (1 + F · t / S) ^ (−w20)          где F = 0.9 ^ (−1 / w20) − 1

# следующий интервал при желаемом удержании r
I(r, S) = S / F · (r ^ (−1 / w20) − 1)        # при r = 0.9 интервал равен S

# первое повторение
S0(G) = w[G−1]
D0(G) = w4 − e^(w5·(G−1)) + 1

# сложность после ответа: линейное затухание и возврат к среднему
D' = D − w6·(G−3) · (10 − D) / 9
D″ = w7 · D0(4) + (1 − w7) · D'

# успешное вспоминание (G ≥ 2)
S'r = S · (1 + e^w8 · (11 − D) · S^(−w9) · (e^(w10·(1−R)) − 1) · [w15 если Hard] · [w16 если Easy])

# забыл (G = 1)
S'f = min(S, w11 · D^(−w12) · ((S+1)^w13 − 1) · e^(w14·(1−R)))

# повтор в тот же день (шаги обучения)
S' = S · e^(w17·(G − 3 + w18)) · S^(−w19)

Следующий показ через 10 дн. К этому моменту вероятность вспомнить опустится до выбранного уровня.

08Гибридный планировщик

Согласовано

Главное отличие от Anki. Расписание ведётся по навыкам, а проверяется карточка целиком — за один цикл.

Цикл — отрезок сессии, в котором вместе прорабатываются 3–5 карточек одной темы. Задания всех этих карточек перемешиваются: между двумя заданиями одного слова идёт минимум 2 задания других слов. Цикл заканчивается, когда у каждой его карточки пройдены все назначенные задания. Затем начинается следующий цикл — с той же темой или со следующей.

Когда карточка попадает в очередь

Карточка считается «к повторению», если хотя бы у одного навыка due ≤ сегодня. Приоритет — минимальная текущая R среди её навыков: чем сильнее забыто, тем раньше показ.

Какие задания получает карточка в цикле

  1. Обязательные навыки — все, у которых наступил срок.
  2. Попутные навыки — до двух навыков без срока с наименьшей R, если R < 0.95. FSRS корректно учитывает досрочное повторение: при высокой R прирост стабильности небольшой, поэтому сильный навык не раздувается.
  3. На карточку за цикл приходится 2–5 заданий. Если навыков больше, лишние переносятся на следующий цикл, в котором эта карточка окажется.
  4. На каждый навык выбирается задание из карточки: только со статусом ready, тренирующее этот навык, допустимое в текущем режиме (modes). Среди подходящих — то, что дольше всех не показывалось. При равенстве — с большей долей ошибок. Если у навыка нет ни одного готового задания, навык пропускается, а в редакторе карточки появляется предупреждение.
  5. Одно задание может закрыть сразу два навыка (listen-type → listen + spell). Тогда второй навык в этом цикле отдельным заданием не проверяется.

Порядок заданий в цикле и «подсказки»

Задания одного слова в цикле подсказывают друг другу, даже если между ними стоят другие слова: после luggage → багаж вопрос багаж → ? уже не проверяет память. Поэтому:

  • На повторении задания одного слова раскладываются по циклу от трудного к лёгкому: listen → recall / spell → context → recognize. Ответ на вопрос не раскрывается раньше, чем его спросят.
  • Каждый шаблон объявляет, что раскрывает ученику (reveals: [en, ru, audio] в манифесте).
  • Если навык проверяется после того, как его ответ уже был раскрыт раньше в этом цикле, верный ответ пишется в журнал как practice и расписание не меняет. Ошибка засчитывается всегда: не вспомнить даже после подсказки — сильный сигнал.
  • На первом знакомстве порядок обратный, от лёгкого к трудному (§9).

Предложения и чужие слова

У предложения есть targets (ради чего оно показано) и другие известные слова. Оценка полностью идёт навыку context у targets. Остальным знакомым словам пишется только exposure — отметка встречи без пересчёта FSRS, она нужна для статистики и выбора следующих предложений. Правила из uses получают оценку по apply, только если шаблон проверяет именно грамматику (cloze на форму глагола).

Порции и гейт

  1. Тема открывается, когда закрыты её зависимости (requires): у их карточек нет навыков в Learning, и они хотя бы раз прошли повторение.
  2. Из темы берётся порция из batch карточек (по умолчанию 4) в порядке order.
  3. Следующая порция открывается только когда все карточки текущей вышли из Learning и у навыков из gate.skills стабильность не меньше gate.min_stability.
  4. Дневной лимит новых считается в карточках. Если долг по повторениям больше max_backlog_ratio × средний дневной объём, новые слова не вводятся, пока долг не уменьшится.
  5. Грамматическое правило темы вводится до первого предложения, которое его использует.

Первая встреча с порцией из 4 слов

Чтобы за одну сессию пройти все формы, используется схема «расширяющегося повторения»: каждое слово возвращается всё в более трудном задании, а между возвратами идут другие слова порции.

10Сборка сессии

function buildSession(deck, now):
  due    = units.filter(u => u.skills.some(s => s.due <= now + learnAhead))
  topics = groupBy(due, topic).sortBy(minRetrievability)       # самые забытые темы — первыми

  for topic in topics:
    window = take(topic.units, 3..5)                            # окно чередования
    tasks  = window.flatMap(pickExercises)                          # 2–5 заданий на карточку, §8
    queue.push(spreadCycle(tasks, minGap = 2))                  # A1 B1 C1 A2 B2 C2 …

  if newAllowed(now):                                          # лимит, гейт, долг
    batch = nextBatch(openTopics)
    queue.insertAtTopicBoundary(introRounds(batch))              # §9

  return hooks.run('queue.build', queue)                      # плагины могут переупорядочить

spreadCycle раскладывает задания цикла так, чтобы между двумя заданиями одного слова было не меньше minGap других. Порядок заданий одного слова (от трудного к лёгкому) при этом сохраняется. За время цикла слово успевает немного «остыть», и каждое следующее задание действительно проверяет память. Ошибка возвращает задание в этот же цикл, тоже не раньше чем через minGap позиций.

11Прогресс и синхронизация через GitHub

Приложение работает офлайн, локальная копия колоды лежит в IndexedDB. Синхронизация — коммит в репозиторий пользователя через GitHub REST API.

Что меняется при ответе

  1. В журнал устройства journal/<год-месяц>/<устройство>.tsv дописывается строка.
  2. В card.yaml обновляется progress: навык, счётчики, статистика задания, хвост recent, as_of.
  3. Изменения копятся локально и уходят одним коммитом при синхронизации.

Доступ

В MVP — fine-grained personal access token с правом Contents: read & write на один репозиторий. Токен хранится только на устройстве. OAuth и GitHub App требуют небольшого прокси: эндпоинты авторизации GitHub недоступны из браузера из-за CORS. Это этап 3.

Цикл синхронизации

  1. Получить HEAD ветки. Если он не изменился с прошлой синхронизации — сразу шаг 4.
  2. Сравнить деревья через Git Trees API, скачать только изменившиеся файлы.
  3. Слить удалённые изменения с локальными по правилам ниже.
  4. Одним атомарным коммитом через Git Data API (blobs → tree → commit → update ref) записать изменения. Сообщение: review: 42 cards · 3 new · iphone.
  5. Если ref ушёл вперёд, повторить с шага 1.

Слияние без конфликтов

ЧтоПравило
journal/*/<устройство>.tsvКаждое устройство пишет только свой файл и только дописывает, поэтому конфликтов не бывает.
card.yaml → progressЕсли прогресс карточки изменили оба устройства, он пересчитывается: берётся общий предок, к нему применяются строки обоих журналов после его as_of в порядке времени. Результат детерминирован и одинаков на всех устройствах.
card.yaml → content, exercisesТрёхстороннее слияние по полям и по id заданий. Если оба устройства изменили одно поле, остаётся удалённое значение, локальное сохраняется в .zoobrik/conflicts/ и показывается пользователю.
deck.yaml → fsrs.paramsПосле смены параметров progress всех карточек пересчитывается из журнала в фоне.

Распространение колод

  • Опубликовать: экспорт в отдельную ветку или репозиторий без progress и без journal/. Задания со статусом draft по желанию тоже вырезаются.
  • Подписаться на колоду: upstream: gh:author/english-a2 в deck.yaml. Обновления автора вливаются в content и exercises, прогресс не затрагивается. Новые задания приходят готовыми, удалённые автором становятся off и сохраняют статистику.
  • Импорт из Anki (.apkg) с переносом истории в журнал — этап 4.

Кастомизация оформления

15Дизайн-направление

Визуальная метафора — учётная карточка: белый лист, тонкие голубые линейки, красная линия сверху. Это прямой предок флеш-карт, и метафора узнаётся без пояснений. Никаких градиентов и фиолетового. Цвет используется по смыслу: красная линия маркирует активное, четыре цвета оценок совпадают с цветами Anki, чтобы переход был привычным.
