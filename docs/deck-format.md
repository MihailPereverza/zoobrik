# Zoobrik deck format v1

Contract between deck content, the app and the voice tool. The full rationale is in `spec.html`.

## Library

A library (a GitHub repository, a folder on the Mac, or the browser's storage) holds decks:
the repository root may itself be a deck (`deck.yaml` at the top), and every `decks/<id>/` with a `deck.yaml` is another one.
Each deck has its own `topics/`, `templates/` and `journal/`. Card paths in the app include the deck folder.

## Package (`.zoobrik`)

A zip of the deck folder plus `zoobrik.json` (`format: 1`, `id`, `name`, `version`, `lang`, `cards`, `exported`).
Export and import always drop `progress` from cards, `journal/`, `known.yaml`, `fsrs.params` and `source` from `deck.yaml`.
Allowed files: yaml, md, njk, css, js, json, txt and media (mp3, ogg, opus, wav, m4a, webp, png, jpg, gif, svg); no `..`, no hidden folders.

## deck.yaml

```yaml
id: english-a2                   # folder name in decks/ when imported
name: Английский A2
version: 1.0.0                   # optional, shown on update
lang: { target: en-GB, native: ru }   # any BCP 47 tags; codes name the content fields
limits: { new_cards_per_day: 8, reviews_per_day: 250 }
fsrs: { retention: 0.9, params: null, learning_steps: [10m] }   # one memory per card; params: written by the optimizer
cycle: { max_per_day: 3 }        # graded exercises per card per day, practice excluded
ladder: [recognize, recall, context, listen, apply]   # exercise formats from easy to hard, see below
listening: { min_coverage: 0.95 } # a clip opens when the learner knows this share of its words
voice: { en: bf_emma }           # Kokoro voice per language, optional
source:                          # written by the app on import, never by hand
  url: github:owner/repo/decks/x@main
  media: https://raw.githubusercontent.com/owner/repo/main/decks/x   # audio fetched from here when not copied
```

## Layout

```
decks/<deck>/
  deck.yaml
  topics/<topic-id>/
    topic.yaml
    exercises.yaml            # optional: exercises spanning several cards (match-pairs)
    <card-id>/
      card.yaml
      theory.md               # optional (grammar cards), referenced by content.theory
      exercises/*.md          # optional markdown exercises
      word.mp3, ex1.mp3 ...   # generated by tools/voice.py
  placement.yaml              # optional: frequency list for the placement test
  known.yaml                  # written by the app: the learner's own vocabulary
  journal/<YYYY-MM>/<device>.tsv
```

Ids: lowercase latin, digits, `-`. Card id is unique within the deck.

## topic.yaml

```yaml
id: appearance-hair
title: Внешность — волосы        # shown in UI
description: Цвет, длина и форма волос, борода и усы.
kind: vocab                      # vocab | grammar
level: A2
requires: []                     # topic ids that must be started first
batch: 4                         # new cards per portion
order: [hair, curly, wavy, ...]  # introduction order, every card of the topic exactly once
```

## glossary.yaml (tap to translate)

Every English word in an exercise can be tapped (long-pressed on answer buttons) to see its translation. The app looks up
the longest set phrase around the word (`kind of`, `in front of`, `look for`), then the word, then its base form
(`wears` → `wear`, `carrying` → `carry`, `stopped` → `stop`). Card terms are included automatically; `glossary.yaml` next
to `deck.yaml` covers every other word and phrase: `word: перевод`. Quote keys and values YAML would misread (`"yes"`, `": "`).

## placement.yaml (placement test)

Authored, part of the deck. The most frequent words of the target language, most frequent first (about 1000):

```yaml
words:
  - { en: be, ru: быть, forms: [am, is, are, was, were, been] }
  - { en: go, ru: идти, forms: [went, gone] }
  - { en: city, ru: город }
```

`forms` lists only irregular forms; regular `-s/-es/-ed/-ing/-er/-est/-ly` are recognised automatically. When a deck has
`placement.yaml` and no `known.yaml`, the home screen offers the test; the deck screen (Колоды → ⋯) can retake it.

The test goes through the list in bands of 100 words. Each band starts with 10 random words of the band; the learner taps
the words they do not know ("Проверить себя" shows the translations). 9–10 known: the whole band counts as known except the
tapped words. 4–8 known: the rest of the band is shown 10 words per screen. 3 or fewer known in two bands in a row: the test
stops and everything after stays unknown (a single weak band is skipped and the test goes on).

## known.yaml (written by the app)

The learner's own vocabulary for this deck, in placement order:

```yaml
tested: 2026-10-07          # day of the last placement test
words: [the, be, go, ...]   # placement lemmas the learner knows, plus words added with «знаю»
unknown: [scarf, ...]       # words explicitly tapped as unknown in the test (informational)
```

It is personal state like `progress`: saved and synced the same way (a pending commit in GitHub mode, the deck folder in
dev mode, the browser in local mode), never exported and kept when the deck is updated from its author. Retaking the test
replaces it. A word missing from `words` is unknown. Once the file exists, the tap-to-translate tip has a «знаю» button
that adds the tapped word (or set phrase) as its placement lemma (`went` → `go`). Without `known.yaml` nothing is locked by
vocabulary, except listening cards.

## Scheduling: one memory, a ladder of formats

Each card has one FSRS memory (`progress.memory`) and a step on the ladder (`progress.rung`). A due card gets one
exercise from its step; an exercise sits on the lowest ladder skill it trains (`spell` counts as `recall`).
A new word stays on the ladder until it passes every format: Good climbs a step (two when the learner typed or heard the
answer rather than picked it), Easy two, Hard stays, Again goes a step
down, and the word comes back after a short wait (`fsrs.ladder_steps`, default 5m, 10m, 30m, 1h; 5m after Again).
Passing the top step sets `progress.learned` and hands the card to FSRS with intervals of a day and more; only then
`cycle.max_per_day` limits its reviews. Old per-skill `progress.skills` are read once as the card's weakest skill.

New cards come as a portion of words from the first open vocabulary topic plus one rule from the first open grammar
topic (`kind: grammar`), in `deck.yaml` order; `limits.new_rules_per_day` (default 2) caps rules. A topic opens once each
vocabulary topic in its `requires` has a portion started and each grammar topic in it is learned (every card passed the
ladder). Inside a grammar topic the next rule waits until the earlier ones are learned. A session brings its new portion from the start, one new item after every two reviews, so a short session still teaches
something new. «Ещё новые слова» in the app takes
a portion past the daily limits.

Which exercise of a rung: the one shown longest ago, easy before hard while learning. From the third rung on and in reviews
of learned cards, exercises where the learner produces the answer — typing (`fuzzy`/`exact` checks, markdown gaps) or
listening — win over choices and chips; every fourth review keeps the full mix. So a card needs choices/chips for its first
formats and enough typing and listening exercises for the rest (see «Minimum exercise set»).

## Prerequisites: nothing before it is taught

The learner never meets a word, a meaning or a construction that was not taught first. Three mechanisms keep it so:

| what | how it is found | what happens |
|---|---|---|
| words (Rule B) | placement test + `known.yaml` + terms of introduced cards | an exercise with an unknown word is not asked until a card teaches the word |
| grammar (Rule G) | `detect:` patterns of rule cards | an exercise using a construction is not asked until its rule card is **learned** |
| anything else | `needs: [card-id, …]` on an exercise | not asked until those cards are introduced |
| a whole card | `needs: [card-id, …]` at the top of card.yaml | not introduced until those cards are learned (e.g. the rules a listening clip is built on) |

A rule card (or a word card that teaches a set phrase such as *in the evening*) lists regular expressions (JavaScript, case-insensitive, matched against each sentence of an exercise with its
gaps filled by the answer — question text, options and chips) that find its construction:

```yaml
id: pc-form
kind: grammar
detect:
  - "\\b(?:am|is|are|'m|'s|'re)\\s+(?!interesting\\b|boring\\b)[a-z]{2,}ing\\b"    # She's wearing…
content: { title: …, theory: theory.md, examples: [...] }
```

Keep patterns precise: a false match only delays an exercise, but a missed one lets a construction through. An exercise
that matches by accident (an `-ing` adjective, a quoted example of a form) lists the rule in `allow_rules: [pc-form]`.
Card **examples** are shown on the intro screen and cannot wait: an example must use only rules taught before the card.
Exercise fields:

```yaml
needs: [present-simple-he-she]   # wait for these cards (ids or topic/id) to be introduced
allow: [Anna]                    # words that never lock this exercise (names, quoted foreign words)
allow_rules: [pc-form]           # rule cards whose detect matched by mistake
```

The teaching order is computed like the scheduler does it: portions of `batch` words from the first open vocabulary topic,
each with one rule from the first open grammar topic. `npm run lexicon -- <deck> --assume-top 1387` (in `web/`) prints it
against both rules: unknown words, «card examples shown before their rule» (must be 0 — rewrite the example or move the
card) and «exercises waiting for a later rule» (fine when the card still has enough exercises at each rung; otherwise move
the rule earlier or add the card's topic a `requires:` on the grammar topic). In the app the same report is in
«Настройки → Проверить колоду».

## Exercise difficulty

`difficulty: 1…5` on an exercise (or in a markdown exercise's frontmatter) overrides the template's difficulty. While a card
is being learned, its exercises go from easy to hard; reviews mix them. Use 4–5 for trap exercises.

## Listening cards

`kind: listening` cards live in `topics/listening/<id>/` and are made by `tools/listening.py` from `tools/listening-clips.yaml`
(licensed sources only: public domain or Creative Commons; the licence is stored in `content.source`):

- `clip.mp4` (360p, subtitles burned into the source are cropped with `crop_bottom`) or `clip.mp3`, `poster.jpg`;
- `transcript.yaml` — `segments: [{n, start, end, speaker?, text, words: [[word, start, end], …]}]`, timed by Whisper and
  aligned to the official script when there is one;
- `seg<N>.mp3` — audio of transcript line N (1.2–12 s) for dictations (`listen-type`).

The app shows the player above every exercise of the card; the transcript opens on demand (counts as a hint), follows the
audio word by word, lines seek on tap and words translate on tap. Exercises: markdown questions (choice, True/False/Not said,
gaps, `[[order: a · b · c]]` to order events), dictations, and `open-answer` (free text graded by an OpenRouter model chosen
by the learner, or self-checked against `model_answer`). Authoring rules: `docs/listening-authoring.md`.

## Movie clips (playphrase.me)

`clip-type` and `clip-choice` exercises play a short scene of a film or a TV series found on
[playphrase.me](https://www.playphrase.me). **The deck stores references only**: the clip's video URL
(`https://www.playphrase.me/video/eng/<movie>/<id>.mp4`), its subtitle line with word timings and the film credit. The
app streams the video from playphrase.me when the exercise is shown; no video, frame or audio of a clip is ever
downloaded into the deck or the repository (`validate_deck.py` accepts nothing but a playphrase.me URL in `video`).
Offline or when a clip is gone, the exercise shows «Видео недоступно» and «Пропустить».

| param | |
|---|---|
| `video` | playphrase.me video URL |
| `text` | the whole line as subtitled; Rule B and Rule G apply to it |
| `words` | `[[word, start ms, end ms], …]` relative to the clip: the line lights up word by word after the answer |
| `source` | `{ title: "Film (year)", url: <IMDb page> }`, shown small under the video |
| `answer`, `accept[]` | `clip-type`: what to type — the gap words, or the whole line for a dictation |
| `gap` | `clip-type`: the target words, an exact part of `text`, shown as `___` in the line; without `gap` nothing of the line is shown before the answer (dictation) |
| `question`, `options[3–4]` | `clip-choice`: a Russian question («Что сказал герой?») and lines that differ in 1–2 words (another time phrase, another tense) |
| `focus` | words set in bold in the line after the answer (a dictation or a choice); for `clip-type` with `gap` the gap is bold |
| `translation`, `explanation` | shown after the answer |

`video`, `words`, `source` and `focus` are not learner text and never lock an exercise; `text`, `gap`, `answer` and the
options do (unknown words and untaught grammar wait as usual). A dictation should `accept` the line without punctuation.

`tools/playphrase.py <deck> [--cards a,b] [--topics t1,t2] [--per-card N] [--dry-run]` adds them: it searches
playphrase.me for each card (word and phrase cards: the term; grammar cards: phrases its `detect` finds in the examples,
or `queries:` in `tools/playphrase-clips.yaml`), keeps clips that are not sensitive, 3–14 words, at most 7 s, clearly
spoken (word scores ≥ 0.6 on average), checks each line against the words and rules known at the card's teaching step
(`web/scripts/clips-filter.ts`: placement top 1387 plus the cards introduced by then), picks the shortest from different
films and appends `v1, v2, …` to the card: a `clip-type` gap on the target words (difficulty 3), a dictation of a line up
to 8 words (difficulty 4) and a `clip-choice` (difficulty 2). Existing exercises and `progress` stay as they are. The Russian
side (translation, explanations, wrong options) is written by hand in `tools/playphrase-clips.yaml` under the clip id; a
picked clip without notes is listed in `tools/.cache/playphrase/todo.yaml`. Searching is polite: an anonymous session
like a browser visit (kept in memory only), one request per 2 s, at most `--max-searches` (150) per run, every answer
cached in `tools/.cache/playphrase/` and never asked again.

## Several voices

`tools/voice.py` voices every recording with several engines (default: `qwen`, `turbo`, `melo`, `piper`) and keeps only
takes that pass a listening check (Whisper hears the words, a phoneme recogniser hears the sounds). The first passing
voice is written to the file named in the card (`word.mp3`), every other one next to it as `word.<voice>.mp3`.
The app picks one voice per exercise, so a learner gets used to different speakers; decks with a single file per
recording work as before. Loudness is levelled across voices.

## Human recordings and credits

A recording by a person sits next to the synthetic ones as `<name>.human.mp3` (a second speaker: `.human-2.mp3`). The app
always plays a human take when there is one; synthetic voices only fill the gaps. `tools/human_audio.py` downloads them
from open sources (Wikimedia Commons / Lingua Libre for words, Tatoeba for sentences), levels them to −16 LUFS when the
licence allows changes (CC0, CC BY, CC BY-SA) and keeps no-derivatives files (Charles Kelly's Tatoeba recordings,
CC BY-NC-ND 3.0) byte for byte. Every such file is listed in `credits.yaml`, shown in «Настройки → Авторы записей»:

```yaml
notices: ["verbatim text a licence requires"]
files:
  topics/basics/common/ex1.human.mp3: { author: Charles Kelly (CK), license: CC BY-NC-ND 3.0, source: https://tatoeba.org/audio/download/21102, text: "Tatoeba #294881 · CC BY 2.0 FR" }
```

A deck with non-commercial recordings must stay free and without ads.

## card.yaml

Content fields may be named by language code of `lang` (`en`, `ru`, `alt_ru`; `es`, `ru` …) or neutrally
(`term`, `meaning`, `alt`, and `term`/`meaning` in examples). Templates see only the neutral names.
Old template ids (`en-ru-choice`, `ru-en-type`, `listen-choose-ru`, `sentence-build-*`) keep working as aliases.

```yaml
id: curly
kind: word                       # word | phrase | idiom | grammar
tags: [appearance]               # optional, used by search and practice filters
content:
  en: curly
  ru: кудрявый, вьющийся
  alt_ru: [кучерявый]            # other accepted Russian answers
  pos: adjective                 # noun | verb | adjective | adverb | phrase | idiom | phrasal verb | preposition
  ipa: ˈkɜːli                    # British, without slashes
  audio: word.mp3                # always word.mp3 for word/phrase/idiom cards
  note: |                        # markdown, optional: usage, traps, collocations
    О волосах: **curly hair**. Мелкие кудри — *frizzy*.
  confusables: [wavy, straight]  # card ids or plain words
  examples:                      # 3–4 natural, simple (A2–B1), varied sentences
    - id: ex1
      en: She has curly hair.
      ru: У неё кудрявые волосы.
      audio: ex1.mp3             # always <example id>.mp3
exercises: [...]
```

Grammar cards: `kind: grammar`, `content: { title, formula, theory: theory.md, examples: [...] }` (no `en`/`ru`/`audio` word fields; `title` is used where a word card shows `en`).

Audio rule: the only audio files are `word.mp3` (from `content.en`, voiced by IPA when present) and `<example id>.mp3` (from `examples[].en`). Any `audio` param in an exercise must point to one of these files. Need a sentence voiced → add it to `examples`.

## Exercise record

```yaml
- id: e3                         # unique within the card
  template: build-term # template id (see below) or ./views/<id>
  skill: context                 # one skill or a list
  status: ready                  # draft | ready | off
  from: examples.ex1             # optional: the content the exercise was built from
  params: { ... }                # exactly the params of the template
```

Every param value is literal data that is shown to the learner. Options/extra words must be plausible but unambiguously wrong. Markdown is allowed in `explanation`, `instruction`, `hint`, `note`.

Common optional params for every gradable template: `explanation` (markdown, shown after the answer).

## Skills

`recognize` (en → meaning), `recall` (meaning → en), `listen` (sound → form/meaning), `spell` (exact writing), `context` (use in a sentence), `apply` (grammar rule).

## Templates (core v1)

| template | skills | params | check |
|---|---|---|---|
| `intro` | — | `{}` (renders card content) | none |
| `meaning-choice` | recognize | `word`, `answer`, `options[4]` (answer included), `audio?` | choice |
| `meaning-flip` | recognize | `front`, `back`, `audio?`, `note?` | manual 1–4 |
| `term-type` | recall, spell | `prompt`, `answer`, `accept[]`, `hint?` | fuzzy |
| `term-choice` | recall | `prompt`, `answer`, `options[4]` | choice |
| `build-term` | context | `prompt` (ru), `answer` (en), `accept[]`, `extra[2–4]`, `audio?` | tokens |
| `build-meaning` | context | `prompt` (en), `audio?`, `answer` (ru), `accept[]`, `extra[2–4]` | tokens |
| `listen-type` | listen, spell | `audio`, `answer`, `accept[]`, `translation` | fuzzy |
| `listen-choice` | listen | `audio`, `answer` (ru), `options[4]` | choice |
| `cloze-type` | context / apply | `text` (gap as `___`), `answer`, `accept[]`, `hint?`, `translation?`, `audio?` | fuzzy |
| `cloze-choice` | context / apply | `text` (gap as `___`), `answer`, `options[2–4]`, `instruction?`, `translation?`, `audio?` | choice |
| `grammar-fix` | apply | `wrong`, `answer`, `accept[]`, `translation?`, `audio?` | fuzzy |
| `word-order` | apply / context | `instruction`, `tokens[]` (shuffled for display), `answer`, `accept[]`, `translation?`, `audio?` | tokens |
| `match-pairs` | recognize | `pairs: [[en, ru], ...]` (4–6) — topic `exercises.yaml` only | pairs |
| `clip-type` | listen, spell | `video`, `text`, `words`, `source`, `answer`, `accept[]`, `gap?`, `focus?`, `translation?` (see «Movie clips») | fuzzy |
| `clip-choice` | listen | `video`, `text`, `words`, `source`, `question`, `answer`, `options[3–4]`, `focus?`, `translation?` | choice |
| `md` | any | markdown file in `exercises/` | from markup |

`audio` for `meaning-choice`, `meaning-flip` defaults to `word.mp3` when omitted.

Token rules for `tokens` check: answer is split by spaces; punctuation stays attached to the word (`luggage.`), so chips look like `I` `can't` `find` `my` `luggage.`. `extra` words must not be tokens of the answer or of any `accept` variant.

## Topic exercises.yaml

```yaml
- id: t1
  template: match-pairs
  status: ready
  cards: { curly: recognize, wavy: recognize, straight: recognize, bald: recognize, beard: recognize }
  params:
    pairs: [[curly, кудрявый], [wavy, волнистый], [straight, прямой], [bald, лысый], [beard, борода]]
```

## Markdown exercise (exercises/*.md)

```md
---
id: md1
skill: apply
status: ready
---
Prompt text with **markdown**.

- [x] correct option          ← choice (one [x])
- [ ] wrong option

He [[goes|is going]] to work. ← typed gap, `|` separates accepted answers
[[chips: She · goes · to · work. | go · going]]  ← chip builder: answer tokens, then extras
!audio(ex1.mp3)               ← play button for a card audio file

???

Back side / explanation, shown after the answer. Without choices or gaps the exercise is a flip card graded 1–4.
```

A markdown exercise uses one interaction kind: options, gaps, or one chips line.

## Minimum exercise set per word card

`intro`, `meaning-choice`, `term-type`, `listen-choice` or `listen-type` (word), `build-term` (ex1), `build-meaning` (ex2), `listen-type` (a short example), `cloze-type` (an example with the word gapped). Add trap exercises (`cloze-choice`) for confusable pairs. All curated exercises get `status: ready`.

Production (typing and listening) for the later formats: at least 5 per word card — `term-type`, `listen-type` of the word,
1–2 example dictations, `cloze-type` in two sentences, and a typed sentence translation (`term-type` with a Russian sentence
as `prompt`, difficulty 4). A rule card: at least half of its exercises typed or listened — `cloze-type`, `grammar-fix`,
markdown gap texts, typed translations that need the rule, 2–3 dictations of its examples. Choices and chips stay for
difficulty 1–2.

A word card trains the word; an exercise that trains a rule (adjective order, tense choice, -s) belongs to the rule card.
